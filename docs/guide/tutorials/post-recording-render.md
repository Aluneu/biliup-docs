# 录后合成：遮挡、图片与弹幕一次导出

「录后合成」（renders）用于**下播之后再加工**：保留纯净的源录像与弹幕 XML，在回看工作台里加遮挡、图片层、压制弹幕，最后一次性编码成 MP4。

::: tip 与「录制时遮挡」的区别
| | 录制时遮挡 | 录后合成 |
|---|---|---|
| 生效时机 | 分段关闭后立刻处理 | 下播后手动导出 |
| 源片 | 被替换为已遮挡版本（原片隔离为 `.unmasked`） | **原片、XML、图片全部保留** |
| 适合 | 必须立刻消除敏感画面 | 想保留素材、之后再决定怎么剪 |
:::

---

## 一、先让房间保留纯净素材

「直播管理 → 直播间 → 配置覆写 → 下载设置 → **使用本地素材录制预设**」会写入：

- 下载器 `mesio`；
- 上传器 `Noop`；
- 碎片过滤 `0`；
- 后处理空列表；
- 录制阶段遮挡**关闭**。

它只改当前房间的覆写，且不能用于 `sync-downloader`。

---

## 二、在工作台编辑

「剪辑台 → 直播场次 → 回看 → **画面与弹幕**」：

- **图层**：马赛克、模糊、纯色，以及 PNG / JPEG 图片；
- 勾选「画面拖拽编辑」后可直接拖拽缩放，左侧 / 顶部 / 宽度 / 高度 / 不透明度可数值微调；
- 图层可排序，并可添加**多个时间区间**（只在区间内生效）；
- 图片以资源 ID 保存，**不接受直接提交服务器路径**；
- 打开「压制弹幕」后，预览与导出共用同一套 ASS 流程，可调字体、字号、透明度、描边、速度、密度与偏移（**正偏移 = 延后**）。

---

## 三、导出

| 操作 | 说明 |
|---|---|
| 合成导出选段 | 把精确剪辑、遮挡、图片与弹幕压制放进**同一次** FFmpeg 编码（多源分段同一滤镜图），输出 MP4 |
| 导出整场 MP4 | 仅场次结束后可用 |

- 首次导出前，在「空间配置」确认 FFmpeg 可用；
- 弹幕还需要 FFmpeg 带 **libass**，以及随包字体；
- 成品会出现在「压制任务」列表里，可播放、下载。

::: warning 不会自动投稿
合成结果只是本地文件，biliup **不会自动投稿**；需要投稿请走投稿模板或手动上传。
:::

---

## 四、字体与弹幕转换

- XML → ASS 已内置为**原生 Rust 实现**（排版派生自 DanmakuFactory），**无需再安装 DanmakuFactory**；旧的 `danmaku_factory_path` 仍能加载配置，但不再读取，填了只会告警。
- CLI、桌面版与 Docker 镜像随包分发 **Noto Sans CJK SC** 与 **Noto Emoji**（独立资源文件，不内嵌进二进制）。CLI 用可执行文件旁的 `render-tools/fonts/`。
- 自定义字体：设置 `render_fonts_dir`（填目录本身或它下面的 `fonts/` 都可以）。
- Python 包只有基础 API，**不含字体与录制服务**。

---

## 五、任务与源片

侧栏「**压制任务**」（`/renders`）可以筛选、取消、重试、播放、下载。

- 取消或失败**不会删除**原视频、XML 与图片；
- 任务使用**创建时的配置与图片快照**，重试会新建任务；
- 转换在进程内完成，超过 **120 秒**或取消即报错。

---

## 六、GPU 编码

「视频编码」可选：自动、CPU、具体编码器与 DRM 设备节点，随场次保存。

- 可用编码器：`h264_nvenc`、`h264_qsv`、`h264_vaapi`、`h264_amf`、`libx264`；
- **手动指定不可用会直接失败**，只有「自动」模式才回退 CPU；
- 列在 `ffmpeg -encoders` 里不代表驱动真的可用；
- ASS 弹幕仍由 libass 处理（CPU 侧）。

---

## 七、与自动处理、切片的关系

- 自动分段处理与工作台导出统一存到工作目录下的 `renders/<场次ID>/`（没有场次信息时存 `renders/`）；该目录是固定约定，**没有配置项**。
- 想对每个分段自动做「遮挡 + 弹幕」，可在直播间「处理流程」里给 `segment_processor` 加一个 `render` 步骤（需要开启弹幕录制）；旧的 `mosaic_config` 会自动转成同一步骤。
