# 多机录制 Fleet

一台机器录不过来，或者想把不同网络位置的机器放在一起管理时，用 Fleet：**一台控制面 + 若干节点**。控制面负责分派房间、下发配置、汇总状态与告警；每个节点仍然自己录制、自己投稿，录像不经过控制面。

> v1.3.1 起 `biliup server` **默认就带着控制面启动**，不需要额外的 `--controller`。单机使用时一切照旧，不会有任何行为变化。

---

## 三种运行形态

| 形态 | 触发条件 | 行为 |
|---|---|---|
| 单机 | 默认 | 控制面已就绪，但没有节点加入；直播间、模板、配置都按本机使用 |
| 控制面 | 默认（或显式 `--controller`） | 接受节点加入、分派房间、下发配置、收告警；「本机」也可以启用成录制节点 |
| 节点 | 工作目录有 `data/node.json`，或给了加入票据 | 作为控制面的工作节点运行；此时 relay 相关参数被忽略 |

::: info 节点身份优先
只要存在 `data/node.json` 或加入票据，进程就**以节点身份启动**——这是为了避免「一台本该是节点的机器自己又变成控制面」。
要回到单机，先执行 `biliup node leave`（会删除本地凭据）。
:::

---

## 前置条件

- 所有机器上 biliup 版本尽量一致（迁移只前进不回滚，版本差异过大可能出现字段不兼容）。
- 节点必须能**主动出站**连到控制面的 relay（默认 TCP `19160`）。加密内建、无需证书，也不需要公网 IP。
- 控制面的 `data/fleet.sqlite3` 含**控制面私钥**，必须备份。

---

## 第一步：启动控制面

```bash
biliup server --bind 0.0.0.0 --auth
```

默认行为：

- relay 监听 `0.0.0.0:19160`；端口被占用时**自动挑一个空闲端口**，加入票据里带的是实际端口；
- 显式写了 `--controller` 或 relay 参数时，监听失败会**直接报错**，不再悄悄降级；
- `--relay-listen off` 不起内嵌 relay，此时必须用 `--relay-url` 指定外部 relay（用于域名、端口转发、反向代理）；
- 网卡上没有公网地址时，用 `--relay-url` 声明节点能访问到的地址（可重复）。

控制面的端口（`--port`，默认 `19159`）是 WebUI，节点不需要访问它；节点只连 relay。

---

## 第二步：生成票据并加入节点

1. 控制面 →「**任务平台 › 节点管理**」→「添加节点」，生成一张以 `bfleet` 开头的加入票据；
2. 在节点机上执行：

```bash
cd /opt/biliup          # biliup 服务的工作目录
biliup node join bfleet_xxxxxxxx
# 需要下发钩子 / ffmpeg 参数时再加：
biliup node join bfleet_xxxxxxxx --allow-hooks
```

3. 重启节点的 `biliup server` 生效；
4. Docker 部署的节点用环境变量传票据：`BILIUP_JOIN_TICKET=bfleet_xxxxxxxx`。

::: danger --allow-hooks 等于交出 shell
带钩子的房间会执行 `*processor` 里的命令，带 ffmpeg 参数的房间能让 ffmpeg 往任意路径写文件。只有在你完全信任控制面时才加 `--allow-hooks`。

没有 `--allow-hooks` 的节点不会被派到这类房间：已经派过去的会在节点升级后**被节点移除并停止录制**，控制面显示失败并给出原因。要继续录，把房间改派到允许钩子的节点，或者清空房间的钩子 / ffmpeg 参数。
:::

其它节点命令：

```bash
biliup node status     # 查看本机凭据，不连控制面
biliup node leave      # 通知控制面移除本节点，并删除 data/node.json
```

---

## 第三步：分派房间

「任务平台 › 节点管理 › 房间」里可以：

- **手动指定**某个房间由哪个节点录；
- 或按**负载自动选择**（谁空闲给谁）；
- 改派时等原节点释放后再接手；「强制迁移」会直接抢，正在录的分段可能受影响。

控制面的「本机」也可以启用为录制节点，适合把一台常开的机器既当管理面又当录机。

## 标签、配置下发与告警

### 节点标签

给节点打标签（例如 `region=cn-east`、`gpu=yes`），房间可以要求标签，只有满足条件的节点才会被派到。适合按线路 / 机房 / 硬件能力分组。

### 统一下发配置

控制面的「Fleet 配置」页可以把全局配置下发给节点，也可以在节点上做覆写：

- **Cookie、登录密码留在节点本地**，不会随配置下发；
- 下发有历史记录，可以看每个节点应用到了哪个版本；
- `/nodes/config`、`/nodes/template` 是独立页面（v1.3.1 起由弹窗改为页面）。

### 告警

支持离线、磁盘不足、投稿失败几类告警。告警在控制面汇总，节点不需要各自的通知渠道。

## 主备（HA）

同一组房间可以配对成主备：主机录制，备机待命；主机故障时备机接管，接管按**会话级上传仲裁**，避免两边同时投稿。配对与状态同步在「节点」页面的主备面板里操作，双向同步设置与 Cookie。

::: warning 主备不是备份
主备解决的是「机器挂了继续录」，不解决「录完的录像被删了」。录像与 `data/` 仍然要自己做备份。
:::

## 备份清单

| 文件 | 内容 | 丢失后果 |
|---|---|---|
| `data/fleet.sqlite3` | 控制面：节点、房间分派、私钥 | **全部节点需要重新加入** |
| `data/node.json`（节点，权限 0600） | 节点凭据 | 重新 `node join` |
| `data/data.sqlite3` | 直播间、模板、场次、任务状态 | 配置与历史全丢 |
| 录像目录 | 分段与弹幕 | 无法补录 |

> 升级前先备份 `data/`：迁移不能回滚。

## 常见问题

### 节点显示离线

1. 节点能否出站访问控制面 relay 的端口（默认 19160，可能被自动换过，以票据里的为准）；
2. 控制面是否换了地址而票据没重新生成——重新「添加节点」拿新票据；
3. 节点是否因为用了 `--config` 启动而无法作为节点（已加入的节点不能用 `--config` 启动）。

### 房间一直没人录

- 房间要求的标签没有任何节点满足；
- 房间带钩子 / ffmpeg 参数，但没有节点带 `--allow-hooks`；
- 原节点还没释放（改派会等待），检查节点上的录制状态。

### 想彻底关掉 Fleet

单机用户不需要做任何事。若连 relay 端口都不想开：`biliup server --relay-listen off`。
