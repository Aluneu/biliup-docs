# 全局设置

::: info
在 WebUI「空间配置」中保存全局配置后，下载 / 上传线程池、日志级别、FFmpeg 路径会**立即应用**；其余项（下载器、投稿接口、分段规则等）在下一次录制 / 上传任务时读取，个别底层行为需**重启 biliup** 才能完全生效。无特殊需求不建议修改默认值。
:::


---

## 下载器

### mesio（默认）

- **当前版本的默认下载器**，v1.2.9 起取代 `stream-gears`。
- 进程内实现的 FLV / HLS 下载与修复管线，**不依赖任何外部进程**。
- 无需安装 FFmpeg 或 streamlink，部署最轻。

### stream-gears

- 上一版本的默认下载器（v1.2.9 起默认改为 `mesio`），无需安装 FFmpeg。
- 自动处理主播 PK 等导致的分辨率变化，防止视频花屏。
- v1.3.0 起支持 HLS（TS 与 fMP4，含 B站 `hls_fmp4`），容器跟随源站：TS 存 `.ts`，fMP4 存 `.mp4`。
- v1.3.0 起断流、读超时、下播时不再丢失最后一个 GOP；「收尾丢流尾」只是当初改用 `mesio` 的历史原因，现已修复。

### streamlink

- HLS 多线程下载。
- 自动识别是否需要 HLS 模式，不支持的流将回退到 FFmpeg。
- 需要安装 FFmpeg。

### ffmpeg

- 最通用的音视频下载工具，兼容性强。
- 需要安装 FFmpeg。

### sync-downloader（边录边传）

- 流式视频上传技术，录制过程中实时上传。
- 直播结束后自动投稿送审。
- 极低资源占用：在官方基准条件下（具体直播平台、分辨率 / 码率、上传带宽、CPU 架构、测试版本与失败率以发布基准报告为准），可同时录制多个直播间。`sync-downloader` 为边录边传，录制过程中即开始上传，并非「零落盘」（仍需本地写入临时分段）。

::: warning
上述容量数字为特定基准下的参考值，**不构成任何版本的性能承诺**。实际并发数取决于你的码率、上传带宽与硬件；生产规划请以自己环境的压测为准，不要直接套用数字。
:::

::: warning
强依赖稳定上传带宽，确保上传速率 ≥ 下载速率，否则可能内存溢出（OOM）。
并非所有平台都支持此功能，具体请自行测试。
:::


### ytarchive（仅 YouTube Live）

- 专为 YouTube 直播设计的下载器。
- 支持从直播开始自动录制，无需等待开播。
- 需单独安装 [ytarchive](https://github.com/Kofuua/ytarchive)。

### ffmpeg 外部分段 / 内部分段

- 使用 FFmpeg 进行分段录制，分为外部和内部分段两种模式。
- 适用于需要 FFmpeg 特定参数的场景。

### yt-dlp

- 使用 [yt-dlp](https://github.com/yt-dlp/yt-dlp) 作为下载后端。
- 支持 yt-dlp 兼容的所有平台。

## FFmpeg 路径（ffmpeg_path）

指定 `ffmpeg` 可执行文件的路径。不填时按以下顺序查找：桌面版安装包自带的 → 系统 `PATH` 里的 `ffmpeg`。

**全局生效，主播覆写里不能改**（FFmpeg 是全局共享的外部程序）。

适用于：FFmpeg 装在非标准位置、同时装了多个版本、或不想污染系统 `PATH` 的场景。

---

## 字体目录（render_fonts_dir）

弹幕渲染（浏览器预览与合成导出共用）使用的字体目录。不填时使用随包分发的 Noto Sans CJK SC 与 Noto Emoji。

- 可以填目录本身，也可以填它下面的 `fonts/`。
- CLI 发布包 / 桌面安装包 / Docker 镜像都自带 `render-tools/`（字体与许可）；自行部署时把 `render-tools/` 放在可执行文件旁，或把这里指向该目录。
- 与 `ffmpeg_path` 一样**全局生效，主播覆写里不能改**。

## 视频分段设置

### 分段大小（file_size）

按文件大小分段，单位 Byte。不填时后端默认 `2621440000`（约 2.5 GB）；WebUI 里留空表示**不按大小分段**（会显式写 null）。例：`4294967296` ≈ 4GB。

### 分段时长（segment_time）

按录制时长分段，支持三种写法：`HH:MM:SS`、`MM:SS` 或秒数（如 `3600`）。全局配置保存、主播覆写保存与配置文件加载时都会校验，写错的值会被**直接拒绝并报错**（不会静默降级）；`stream-gears`、`mesio`、`ffmpeg` 三种下载器按同一套规则解析。

WebUI 里可以直接选预设时长，也可以填自定义值；主播的「配置覆写」可以显式继承全局值或关闭分段。

::: tip
分段大小和分段时长可同时设置，先触发哪个就按哪个分段。
:::

## 文件名模板（filename_prefix）

默认：`{streamer}%Y-%m-%dT%H_%M_%S`

示例输出：`主播名2025-03-25T12_46_42`

::: tip
如果修改模板，必须包含 `{streamer}` 变量（放在第一位）和 `%Y-%m-%d %H_%M_%S` 时间戳。
额外支持 `{title}` 变量（直播标题），注意控制字符数不超过 B站限制。
:::

## 分段后处理（segment_processor）

| 处理器 | 说明 |
|--------|------|
| `remux:mp4` | 将录制文件重新封装为 MP4 格式（不重编码，速度快） |
| 自定义脚本 | 可指定 Python 脚本进行自定义处理（如弹幕压制） |

> 此功能需要额外配置，一般用户无需使用。详见[开发者选项](/guide/getting-started/配置/developer-options.html)。

### segment_processor_parallel

分段后处理是否并行执行，默认关闭。开启后多个分段文件的后处理将同时进行，可提高处理速度但会增加资源占用。

## 下载线程池大小（pool1_size）

同时录制的最大直播间数，默认 `5`。

::: tip
如果添加了 6 个主播但只设置 5 个线程，会有一个主播不进行录制。
:::

## 上传设置

### 上传插件（uploader）

| 值 | 说明 |
|---|---|
| `Noop`（默认） | 不自动上传，仅录制 |
| `biliup-rs` | 使用 Rust 引擎上传（推荐） |
| `bili_web` | 使用 Python 引擎上传（兼容旧版） |

### 提交接口（submit_api）

| 值 | 说明 |
|---|---|
| `web`（默认） | Web 接口提交。不配置该字段时同样走 web |
| `app` | App 接口提交 |
| `b-cut-android` / `bcutandroid` | BCut Android 接口提交 |

::: info 默认值变化（v1.3.0 起）
服务端自动投稿 / 编辑稿件原先不配置时走 app 接口；app 接口会拿稿件的第一个标签自动参加活动（转载稿因此常被误挂活动），也更容易被风控。v1.3.0 起改为**默认 web**（[#1801](https://github.com/biliup/biliup/pull/1801)）。命令行 `biliup upload` 不指定 `--submit` 时仍默认 `app`，与此是两条独立路径。
:::

### 上传线路（lines）

| 值 | 说明 |
|---|---|
| `AUTO`（默认） | 自动选择最优线路 |
| `bldsa` / `cnbldsa` | BLDSA 线路（常规 / 国内） |
| `andsa` / `atdsa` | ANDSA 线路（海外） |
| `bda2` / `cnbd` / `anbd` / `atbd` | 百度线路（常规 / 国内 / 海外） |
| `tx` / `cntx` / `antx` / `attx` | 腾讯云线路（常规 / 国内 / 海外） |
| `txa` | 腾讯云备用线路 |
| `alia` | 阿里云线路 |
| `estx` / `akbd` | 其他线路 |

> 上表与 CLI `--line` 的可选值一致（[命令行参考](/guide/configs/config.html)），区别只是全局配置额外接受 `AUTO`。原文档中列出的 `bda`、`qn`（七牛云）在当前版本的线路枚举中已不存在，请勿再使用。

### 上传线程池大小（pool2_size）

同时上传的最大任务数，默认 `3`。

### 单文件并发数（threads）

单个视频文件的分片并发上传数，默认 `3`。上传失败时建议从 `1` 开始逐渐增加。

### 上传重试限制（max_upload_limit）

同一分段因**网络类失败**（断网、DNS 解析失败、超时、5xx）上传失败时，最多上传几次（含第一次）：

- 不填 = 默认 **6 次**；`0` 与 `1` 都是不重试。
- 两次重试之间从 **30 秒**起翻倍等待，单次最长 **5 分钟**（默认 6 次共约 12.5 分钟）。
- **B 站限流、风控等拒绝不会重试**——重试只针对网络问题，避免加剧风控。
- 次数用完仍失败：跳过该分段，**文件保留在本地**，可手动上传或等下次任务。

::: info 该字段已恢复生效（v1.3.0 起）
v1.2.11 的后端一度没有实现这个字段（WebUI 输入框填了也不生效，当时本文档标注过"不再生效"）。v1.3.0 已把它接回网络失败重试逻辑（[#1805](https://github.com/biliup/biliup/pull/1805)），WebUI 表单与配置文件均可正常使用。
:::

### 使用直播封面（use_live_cover）

开启后将自动下载直播间封面并用作投稿封面，默认关闭。

## 画面遮挡（mosaic_config）

`mosaic_config` 保存遮挡区域（JSON）。日常不需要手写：在 WebUI 房间的「画面遮挡」编辑器里圈选区域保存即可，写入的是该主播的覆写；全局字段作为默认值。

启用遮挡后，分段关闭时会先做遮挡再参与碎片过滤与后续处理；**处理后的分段才会进入投稿与切片导出**。切片工作台的快速剪 / 精确剪不会在导出时再加遮罩，需要额外效果请用「合成导出选段」。

> 操作方式见[录制分段、画面遮挡与本地合并](/guide/tutorials/recording-and-masking.html)。

## 未完成的录像

biliup **不会删除未完成的录像**：

- **FLV / TS**（`stream-gears`、`mesio`，以及 ffmpeg 录 FLV / TS）：断流、出错、暂停、删除房间或退出程序时，截断的文件照常作为一个分段保存，并进入上传与后处理。
- **HLS fMP4**：分片整片收齐才写入，截断在分片中间的最后一小段直接丢弃（半个分片会让整个文件结尾解不出来），init segment + 完整分片仍可播放。
- **ffmpeg 录 MP4**（`format: mp4`）：MP4 索引（moov）在录制结束时才写入，被中止的文件无法播放，因此**不进入上传流程**；但文件不会被删除，会以 `.mp4.part` 留在录像目录，可用 untrunc 等工具尝试修复，或自行删除。

## 碎片过滤（filtering_threshold）

过滤因网络波动/主播断流导致的视频碎片，默认 20（单位 MB）。

## 直播合并窗口（live_merge_minutes）

同一主播**下播后多少分钟内再开播**，接着记在上一场里：在「直播历史」里算同一场，断流记录在切片工作台的时间轴上。默认 `10`，`0` = 不合并。

::: tip 只影响归类，不影响投稿
投稿行为不受影响——断流后重新开始的录制**仍然单独投稿**。这个字段只决定「在界面上算一场还是两场」。
:::

适用于开播频繁、经常短时间断流又重连的主播。

## 存储与清理

### 录像保留时长（retention_hours）

投稿后**再保留录像多少小时**。

触发时机：后处理执行 `rm`、或边录边传投稿后删除临时文件时，录像不会立刻删，而是先留这么久，到期后由每分钟一次的清理任务删除。

`0`（默认）= 立即删除，与旧行为一致。

> 例外：被切片工作台引用、或所在场次设了「保留这场」的分段，无论这里怎么设，都会等引用释放后再删。

### 磁盘最低可用空间（min_free_space）

录像所在磁盘的**最低可用空间（字节）**。

低于该阈值时，每分钟一次的清理任务会按「没被引用的最旧 → 被引用的最旧」的顺序删除已录完的分段，直到回到阈值以上。

空或 `0`（默认）= 不启用。

> 只删切片工作台记录过的分段，**不删正在录制的**。适合长期无人值守、磁盘可能被写满的场景。

## 下播延迟检测（delay）

检测到主播下播后延迟指定时间再次确认，避免提前结束导致分稿件。**源码默认值为 `300` 秒（5 分钟）**；请以当前版本 WebUI「空间配置 → 全局设置」中实际显示的值为准。

适用于一天多次开播的主播，根据其下播和再次开播的间隔设置。

---

## 直播事件检测间隔

### event_loop_interval

整体事件循环的检测间隔，单位秒，默认 `30`。例如设置为 `10` 表示每 10 秒检测一次所有主播。

### checker_sleep

单个主播的检测间隔，单位秒，默认 `10`。与 `event_loop_interval` 不同，此值控制对单个主播的轮询频率。

---

## 日志级别（loggers_level）

当前 Rust 版本用 `loggers_level` 设置日志过滤规则，**取值为 RUST_LOG（`EnvFilter`）风格**，例如 `debug`、`tower_http=debug,biliup=trace`。在 WebUI 保存后立即生效，无需重启。

不配置时，服务读取环境变量 `RUST_LOG`；两者都没有则默认 `tower_http=debug,info`。命令行启动可用全局选项 `--rust-log` 指定（见 [CLI 命令行参考](/guide/configs/config.html)）。

::: warning 旧版 `LOGGING` 配置块已失效
`LOGGING.root.level` 等 Python 时代的 logging 配置在 Rust 版本中**不再被读取**（写进配置文件会被静默忽略）。旧文档若提到它，请忽略。
:::

## 边录边传额外保存目录（sync_save_dir）

仅 `sync-downloader`（边录边传）模式生效。设置后，边录边传时会在指定目录额外保存一份录制文件；不设置则不保留本地副本。

可在 WebUI「空间配置 → 全局设置」中填写，也可写进配置文件。

::: warning
强依赖稳定上传带宽，确保上传速率 ≥ 下载速率，否则可能内存溢出（OOM）。
:::

## 直播预览

录制中的房间可以在 WebUI 里点开预览（复用正在录制的那一路流），这两个字段控制它的取流方式与回收策略。

### 取流方式（preview_transport）

| 值 | 说明 |
|---|---|
| `relay`（默认） | 复用正在录制的那一路流、经 biliup 中转，**不会额外拉一路 CDN** |
| `direct` | 浏览器直接向 CDN 拉，省服务器带宽；平台不支持时自动回落到中转 |

`None`（不设置）视同 `relay`。服务器带宽充裕就保持默认；带宽紧张可尝试 `direct`。

### 单条预览最长时长（preview_max_minutes）

单条中转预览连接最长持续多少分钟，到点结束响应、播放器自动重连。

服务端**无法可靠判断客户端是否还在看**——经过会替客户端读完上游的代理或隧道时，关掉播放器 TCP 也不会断——这个字段就是回收这类「幽灵连接」的兜底。

- 不填 = 默认 30 分钟
- `0` = 不限

> 只认全局配置。
