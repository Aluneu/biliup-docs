# 常见问题

> 安装、录制、上传、WebUI、配置分类解答。如有其他问题欢迎到 [GitHub Issues](https://github.com/biliup/biliup/issues) 反馈。

---

## 安装相关

**提示找不到 `biliup` 命令？**

- 通过 npm 安装的，确认 Node.js 的全局 bin 目录在 `PATH` 中：`npm bin -g`（或 `npm config get prefix`）
- 手动下载二进制的，确认解压目录在 `PATH` 中，或直接用完整路径运行
- Docker 用户确认容器已启动：`docker ps -a`

**Windows 下 `.exe` 无法运行？**

- 确认从 [Releases](https://github.com/biliup/biliup/releases/latest) 下载的是当前版本（`biliupR-v*` 压缩包，解压出 `biliup.exe`）
- 安装包 / 二进制未签名时 Windows SmartScreen 可能拦截：点「更多信息」→「仍要运行」
- 检查杀毒软件是否拦截

## 录制相关

**只能录制 5 个主播，第 6 个不工作？**

- 默认下载线程池大小为 5。在「空间配置」中调大「下载线程池大小 (pool1_size)」，**保存后立即生效**，无需重启。

**快手录制不稳定？**

- 快手风控严格，目前没有完美的解决方案。

**HLS 流不会录制（如 B站 APEX 分区）？**

- 默认下载器 `mesio`（v1.2.9 起）已支持 HLS，含 B站 `hls_fmp4` 与 HEVC，无需额外安装。若仍在用 `stream-gears`（不支持 HLS），改用 `mesio`，或将协议配合 `streamlink` + FFmpeg 使用。

**境外服务器录制 B站？**

- 需要自备国内机器反代 `https://api.live.bilibili.com`，将反代地址填入「各平台设置」→「哔哩哔哩」→「直播主 API」。

**斗鱼只能录到「超清」，原画很卡或几分钟就断？**

- 2026-09 起斗鱼把原画 / 蓝光收紧到登录会话。在「空间配置 → 平台设置 → 斗鱼」填入网页版 Cookie（`douyu_cookie`），建议同时配置 `LTP0` + `dy_did` 自动续期。详见[斗鱼平台配置](/guide/getting-started/平台配置/斗鱼.html)。

**日志里一直出现 `Non-monotonous DTS ... previous: 4877, current: 0`？**

- 斗鱼 CDN 切换 / 推流重连时的正常现象。v1.3.0 起会按音视频轨道分别修复时间戳并继续录制，这条日志只是提示，不需要处理。

**录制中断后文件不见了？**

- v1.3.0 起**未完成的录像一律保留**：FLV / TS 照常作为一个分段保存并上传；ffmpeg 录 MP4 被中止时不进入上传流程，但会留下 `.mp4.part` 供手动修复。详见[全局设置 · 未完成的录像](/guide/getting-started/配置/global-config.html)。

## 上传相关

**配置了自动上传但没有上传行为？**

- 检查模板中「上传插件」是否为 `biliup-rs`（非默认的 `Noop`）。
- 检查文件名模板是否包含 `{streamer}`，缺少此标识符将无法识别。

**上传日志出现重试（Retry）相关条目？**

- 分段因断网、超时、5xx 等**网络类失败**会自动重传整个分段：`max_upload_limit`（全局设置）控制最多传几次（含第一次），不填默认 6 次，两次之间从 30 秒起翻倍等待、最长 5 分钟；次数用完仍失败会跳过该分段并把文件留在本地。
- B 站限流、风控等**业务拒绝不会重试**，出现这类报错应降低并发（`threads` 从 1 开始加）或更换上传线路，而不是调大重试次数。

**上传速度慢？**

- B站上传速度主要取决于上行带宽，国内用户使用境外服务器通常更快。

**边录边传对机器要求高吗？**

- 极低：在官方基准条件下约可同时录制 10 个直播间，实际并发取决于码率、上行带宽与硬件（不构成性能承诺）。但需要稳定上传带宽。

## 画质相关

**录制画质模糊/不高？**

- 户外主播码率不稳定，属于源流问题。
- 部分平台（如抖音）需要 Cookie 才能拉取最高画质。
- B站会对上传视频进行二压，原视频 10000 码率上传后可能只有 6000。

## 画面遮挡与录后合成

**开了遮挡，但录像里还是原画面？**

- 遮挡只在**保存设置之后新录制的分段**上生效，旧录像不会追溯处理；
- 需要服务器安装含 `libx264` 的 FFmpeg；处理失败会保留原片，并在日志里说明原因；
- 预览、DVR 回放与 `.part` 临时文件仍然是原画面。

**快速剪 / 精确剪导出的视频没有遮挡和弹幕？**

- 这两个功能只做剪切，**不应用**遮罩与弹幕。需要效果请用回放页的「合成导出选段」，见[录后合成](/guide/tutorials/post-recording-render.html)。

**合成任务一直排队 / 失败？**

- 合成在进程内执行，单次转换超过 120 秒或手动取消会报错；任务使用创建时的配置与图片快照，重试会新建任务；
- 确认 FFmpeg 可用、需要弹幕时带 libass；手动指定的 GPU 编码器不可用会直接失败（「自动」模式才会回退 CPU）。

**还需要安装 DanmakuFactory 吗？**

- 不需要。v1.3.0 起 XML → ASS 转换已内置为原生 Rust 实现；旧配置里的 `danmaku_factory_path` 会被忽略（只告警）。

## WebUI 相关

**无法访问 WebUI？**

- 确认端口 19159 未被防火墙/安全组拦截。
- 检查 `biliup server` 是否正确启动。
- Docker 用户确认端口映射正确。

**修改配置后不生效？**

- 大部分配置在下一次录制 / 上传任务时读取；线程池、日志级别、FFmpeg 路径、`render_fonts_dir` 保存后立即生效。只有个别底层行为需要重启 `biliup`。

**`python -m biliup` 报错 / 找不到模块？**

- v1.3.0 起 Python 包收敛为纯 API，`python -m biliup` 入口已移除。运行完整应用请用原生 CLI、桌面版或 Docker，见[安装部署](/guide/getting-started/安装部署/Linux.html)。

**docker 容器数据丢失？**

- 确保挂载了 `/opt` 目录：`-v /你的目录:/opt`。

## 配置相关

**如何启用自动投稿？**

- 进入「空间配置」→ 在模板中将「上传插件」从 `Noop` 改为 `biliup-rs`。

**如何添加多个 B站账号？**

- 进入「投稿管理」→ 点击左上角图标 →「新增」→ 扫码登录。

**如何修改录制保存路径？**

- 修改 `biliup server` 的运行目录，或 Docker 用户修改 `-v` 挂载路径。
