# WebUI 使用指南

本指南讲解 WebUI 各功能模块，帮助你充分利用 biliup 的管理能力。

::: warning 文档与界面版本说明
本文档基于 **biliup v1.2.11** 对界面路由与功能进行走查。WebUI 界面会随版本变化，路由与导航名称以当前源码为准；**逐页面截图与最终复核建议由前端维护者补充**。如果你的界面与本指南不符，请以实际界面为准，并到 [GitHub 反馈](https://github.com/biliup/biliup/issues)。
:::

## 访问 WebUI

启动 biliup 后，根据部署方式访问对应地址：

| 部署方式 | 默认访问地址 |
|---|---|
| 本地直接运行 | `http://localhost:19159` |
| Docker | `http://<服务器IP>:19159` |
| 自定义端口 | `http://<地址>:<端口>` |

> ⚠️ **未设置 `--auth` 时，WebUI 与 API 均无认证保护。请勿在生产 / 公网环境中不设认证直接暴露端口。**

启动时使用 `--auth` 参数开启 WebUI 认证：

```bash
biliup server --auth
```

::: info 关于 WebUI 登录账号
`--auth` 是布尔开关，**不接收 `user:pass` 参数**。开启后首次访问 WebUI 会进入登录页：**首个账号的用户名固定为 `biliup`（不可修改），由你设置密码**。

自 v1.2.8 起支持多用户，可在「用户管理」页新增其他账号（超级管理员 / 操作员 / 只读观察者三种角色）。

请勿把「WebUI 账号」与「B站投稿账号（通过扫码 / Cookie 添加）」混为一谈——前者只用于登录管理界面，后者用于上传与投稿。
:::

## 导航结构

登录后左侧导航栏分为四组：

| 分组 | 导航项 | 路由 | 作用 |
|---|---|---|---|
| 总览 | 控制台 | `/` | 2 秒内看清"几个在录、有没有问题"，含系统状态 |
| 录制 | 直播管理 | `/streamers` | 管理需要录制的直播间 |
| 录制 | 剪辑台 | `/workbench` | 直播场次、录制文件、实时监视 |
| 录制 | 回放 | `/replay` | 回看某一场直播 / 某个录制文件 |
| 投稿 | 投稿管理 | `/upload-manager` | 管理 B站账号与投稿模板 |
| 投稿 | B站稿件 | `/archives` | 查看已投稿稿件的审核状态 |
| 设置 | 空间配置 | `/dashboard` | 全局设置、各平台设置、开发者选项 |
| 系统 | 实时日志 | `/logviewer` | 在浏览器中查看运行日志 |
| 系统 | 任务平台 | `/status` | 查看任务队列与并发信号量 |
| 系统 | 节点 | `/nodes` | 主备（Fleet）节点管理 |
| 系统 | 用户管理 | `/users` | 新增 / 管理 WebUI 账号与角色 |

> ⚠️ 旧版文档里的 `/job`（"直播历史"页）在当前版本**已不存在**，历史记录请到「剪辑台」的「直播场次」Tab 查看。同时当前版本新增了剪辑台、回放、B站稿件、节点、用户管理等页面，旧文档未覆盖。

## 控制台 (/)

**路径：** `/`

首页，回答"现在有几个在录、有没有异常"。

- 各直播间的录制状态与进度
- 系统状态：CPU、内存、录制目录所在磁盘的可用空间、网速

> 系统资源监控在这个页面。`/status`（任务平台）只看任务队列，不含资源监控。

## 直播管理 (/streamers)

**路径：** `/streamers`

管理所有需要录制的直播间。

### 添加直播源

点击「新增」按钮，支持以下方式：

**方式一：直接粘贴房间链接（推荐）**

支持各平台的完整 URL，biliup 会自动识别平台：

```
# B站
https://live.bilibili.com/123456

# 斗鱼
https://www.douyu.com/123456

# 虎牙
https://www.huya.com/123456

# Twitch
https://www.twitch.tv/username

# YouTube
https://www.youtube.com/watch?v=xxxxx
https://youtu.be/xxxxx
```

**方式二：手动选择平台 + 填写房间号**

适用于链接识别异常的情况。

### 主播卡片

每个已添加的主播以卡片形式展示，包含直播状态、房间标题、开播时间、录制状态与文件大小。

### 单个主播配置项

点击主播卡片的「编辑」按钮，可配置该主播的独立参数（优先级高于全局配置）：

| 配置项 | 说明 |
|---|---|
| 录制开关 | 临时禁用/启用该主播的录制 |
| 上传插件 | 覆盖全局设置，单独指定上传方式（`Noop` = 不自动上传 / `biliup-rs` = 自动上传） |
| 投稿模板 | 指定使用的投稿配置模板 |
| 文件名模板 | 覆盖全局的 `filename_prefix` |
| 分段大小/时长 | 覆盖全局的视频分段规则 |
| 弹幕录制 | 是否录制该主播的弹幕 |
| Cookie/Token | 部分平台需要单独设置认证信息 |

::: danger 默认行为风险（务必先读）
**默认上传器是 `Noop`（只录制、不上传）**，且**新建主播默认带 `rm` 后处理**：即使没有配置上传、或使用了 `Noop`，下播后本地录像也可能被删除。

要让录完自动投稿并保留本地文件，请：① 创建投稿模板并选择 `biliup-rs` 等非 `Noop` 上传器；② 将模板绑定到主播；③ 在确认要保留本地文件前，先移除默认 `rm`，或改用[保留策略](/guide/getting-started/配置/global-config.html#存储与清理)让文件多留一段时间。
:::

### 批量操作

- **全选** — 批量启用/禁用录制
- **批量应用模板** — 为多个主播统一指定投稿模板
- **批量删除** — 移除多个主播（不会删除已录制的文件）

## 剪辑台 (/workbench)

**路径：** `/workbench`

分三个 Tab（当前 Tab 记录在查询串 `?tab=` 里）：

| Tab | 用途 |
|---|---|
| 直播场次 | 每次开播一行，从这里进入回放页 |
| 录制文件 | 按文件回放 |
| 实时监视 | 正在录制的直播间多路同屏 |

「直播场次」取代了旧版的"直播历史"页，录制历史记录在这里查看。

## 回放 (/replay)

**路径：** `/replay`

回看某一场直播或某个录制文件。因为静态导出不支持动态路由，参数走查询串：

```
/replay?session=<场次 id>&t=<场次毫秒>&clip=<切片 id>
```

- `session` — 要回看的场次
- `t` — 起始位置（该场次内的毫秒数）
- `clip` — 要选中高亮的切片

可以从剪辑台的「直播场次」或「录制文件」进入，无需手写这个地址。

---

## 直播间 (/live)

**路径：** `/live`

单个直播间的实时预览页，参数同样走查询串：`/live?streamer=<主播 id>`。

预览复用**正在录制的那一路流**，不会额外拉取 CDN。取流方式与连接回收由[全局设置里的预览相关字段](/guide/getting-started/配置/global-config.html#直播预览)控制。

## 投稿管理 (Upload Manager)

**路径：** `/upload-manager`

管理 B站账号和投稿模板，是自动上传和投稿的配置中心。

### 账号管理

#### 添加 B站账号

1. 进入「投稿管理」→ 点击左上角「新增」
2. 选择「扫码登录」
3. 使用哔哩哔哩 APP 扫描屏幕上显示的二维码
4. 手机确认登录后，页面自动刷新，显示账号信息

> ✅ 登录成功后 Cookie 会自动保存。Cookie 有效期通常为 1-3 个月，过期后请在页面点击「刷新登录」重新扫码。

#### 多账号管理

biliup 支持添加多个 B站账号：

- 不同主播可以指定不同的投稿账号
- 账号列表中显示每个账号的 UID、昵称、Cookie 有效期
- 点击「刷新登录」可重新扫码续期

### 投稿模板

投稿模板是 biliup 的核心概念：**将投稿参数打包成一个可复用的配置**。

#### 创建模板

点击「模板管理」→「新建模板」，填写以下参数：

**基础信息：**

| 参数 | 说明 | 示例 |
|---|---|---|
| 模板名称 | 模板的标识符，便于区分 | `默认投稿`、`游戏区投稿` |
| 投稿账号 | 使用哪个 B站账号投稿 | （选择已登录的账号）|
| 上传器 | 选择实际上传方式（如 `biliup-rs`） | 选 `Noop` 则只录制不上传 |
| 分区 | 视频投稿的分区 | `游戏 → 电子竞技` |
| 标题格式 | 支持变量替换 | `{title} - {date}` |
| 简介 | 视频简介，支持变量 | `录制自 {streamer} 的直播间` |
| 标签 | 视频标签 | `直播录制, {streamer}` |
| 封面 | 封面获取方式 | 自动使用直播封面 / 手动指定 |

**高级参数：**

| 参数 | 说明 |
|---|---|
| 动态 | 投稿时同步发布的动态内容 |
| 延迟发布 | 设定投稿后多久才公开（小时） |
| 合集 (Season) | 将视频加入指定合集 |
| 互动视频 | 启用互动视频功能 |
| 杜比音效 | 开启杜比音效（需 `biliup-rs` 上传插件）|
| 充电专属 | 设为充电专属视频 |

**支持的变量：**

| 变量 | 替换为 |
|---|---|
| `{streamer}` | 主播名 |
| `{title}` | 直播标题 |
| `{date}` | 录制日期 `YYYY-MM-DD` |
| `{time}` | 录制时间 `HH:MM:SS` |
| `{url}` | 直播间链接 |

#### 模板与主播的绑定

在「直播管理」中编辑主播 → 选择「投稿模板」→ 指定该主播使用的模板。

绑定后，该主播录制完成并启用自动上传时，会使用对应模板的参数进行投稿。

> 除了在界面上创建合集，也可以用 [`biliup season` 命令](/guide/configs/config.html#season-管理合集)管理已有合集的稿件与顺序。

## 空间配置 (Dashboard)

**路径：** `/dashboard`

配置中心，包含三个子页面：

### 全局设置

影响所有主播的默认行为，详见[全局设置文档](/guide/getting-started/配置/global-config.html)。

关键参数速查（默认值以当前版本为准）：

| 参数 | 默认值 | 说明 |
|---|---|---|
| 下载器 | `mesio` | 可选 `stream-gears` / `streamlink` / `ffmpeg` / `sync-downloader` 等 |
| 分段大小 | 2.5 GB | 按文件大小分段（Byte）|
| 分段时长 | 不启用 | 按录制时长分段（`HH:MM:SS`）|
| 文件名模板 | `{streamer}%Y-%m-%dT%H_%M_%S` | 录制文件命名格式 |
| 下载线程池大小 | `5` | 同时录制的最大直播间数 |
| 下播延迟检测 | `300` | 延迟 N 秒再次确认下播 |
| 录像保留时长 | `0` | 投稿后再保留多少小时，`0` = 立即删除 |
| 磁盘最低可用空间 | 不启用 | 低于阈值时自动清理已录完的分段 |

### 各平台设置

针对特定平台的配置，详见[各平台设置文档](/guide/getting-started/配置/live-config.html)。

常见需要单独配置的平台：

- **哔哩哔哩** — 直播流协议（flv / hls_fmp4）、Cookie 文件、API 反代地址
- **斗鱼** — CDN 优选、编码、设备 ID
- **虎牙** — CDN 优选
- **YouTube** — cookies 文件（用于访问受限内容）、下载日期范围

### 开发者选项

面向进阶用户，详见[开发者选项文档](/guide/getting-started/配置/developer-options.html)。

主要功能：

- **钩子系统 (Hooks)** — 在录制前 / 分段后 / 下载完成 / 上传后执行自定义脚本
- **Webhook** — 上传完成后向指定 URL 发送 POST 通知
- **分段处理器** — 配置 `remux:mp4` 或自定义 Python 脚本
- **日志级别** — 通过全局配置调整日志详细程度

## 实时日志 (Log Viewer)

**路径：** `/logviewer`

在浏览器中直接查看 biliup 的运行日志，无需 SSH 到服务器。

### 日志级别

| 级别 | 说明 |
|---|---|
| ERROR | 错误，需要关注 |
| WARN | 警告，可能影响功能但不致命 |
| INFO | 一般信息，记录正常操作流程 |
| DEBUG | 调试信息，排查问题时开启 |

### 使用技巧

- **级别过滤** — 只显示某一级别及以上的日志
- **关键词搜索** — 搜索特定关键词（如房间号、错误码）
- **自动滚动** — 开启后新日志自动滚动到可见区域
- **下载日志** — 将当前日志下载到本地，用于反馈问题

> 💡 提交 GitHub Issue 前，请先删除日志中的 Cookie、Token、直播地址与个人路径等敏感信息。

::: info 日志 WebSocket 的认证边界
实时日志通过 `/v1/ws/logs` 推送，可订阅的频道为 `ds_update.log`、`download.log`、`upload.log`（旧文档写的 `postprocessor` 频道已不存在）。

该端点与普通 REST 路由**共用同一套登录守卫**：开启 `--auth` 后未携带有效会话的连接会被拒绝；未开启 `--auth` 时则完全开放。日志内容包含文件名、路径等信息，公网暴露仍建议在反向代理层做访问控制。
:::

## 任务平台 (/status)

**路径：** `/status`

显示服务运行状态与任务并发情况：

| 项目 | 说明 |
|---|---|
| 版本 | 当前 biliup 版本 |
| 房间 | 已添加的直播间 |
| `download_semaphore` | 下载并发信号量：还剩多少下载槽位 |
| `update_semaphore` | 上传并发信号量：还剩多少上传槽位 |

> ⚠️ 本页**不含**系统资源监控，也没有服务的启停控制——CPU / 内存 / 磁盘请看[控制台](#控制台)，服务的重启 / 停止请在命令行或系统服务管理器中操作。

## 节点 (/nodes)

**路径：** `/nodes`

主备（Fleet）节点管理：把多台机器组成一个控制面 + 若干工作节点的结构，由控制面统一分配录制任务并汇总状态。

节点本机侧的加入 / 退出操作用 [`biliup node` 命令](/guide/configs/config.html#node-fleet-节点管理)完成，控制面用 `biliup server --controller` 启动。

> 主备模式的完整流程（配对、票据、状态同步、故障接管）请以实际界面与 `biliup node --help` 为准。

## 用户管理 (/users)

**路径：** `/users`

管理可以登录 WebUI 的账号。自 v1.2.8 起支持多用户与分级权限：

| 角色 | 说明 |
|---|---|
| 超级管理员 | 全部权限 |
| 操作员 | 可进行日常操作，权限受限 |
| 只读观察者 | 只能查看 |

> 首个账号的用户名固定为 `biliup`。忘记密码时可用 [`biliup user reset-password`](/guide/configs/config.html#user-管理-web-登录用户) 重置，不需要动数据库。

## 常见问题

### 无法访问 WebUI

1. 确认 biliup 已正常启动（查看终端输出）
2. 确认访问的端口正确（默认 19159，可通过 `--port` 修改）
3. 如果是远程访问，**确认启动时带了 `--bind 0.0.0.0 --auth`**——默认只监听 `127.0.0.1`，其他设备连不上
4. 如部署在远程服务器，确认防火墙已放行对应端口
5. 如在 Docker 中运行，确认已正确映射端口（`-p 19159:19159`），且 `command` 里带了 `--bind 0.0.0.0`

### 修改配置后不生效

全局配置和平台配置的修改**必须重启 biliup** 才能生效。请在命令行重启进程，或通过系统服务管理器（如 systemd、Docker `restart`）重启。

### 忘记 WebUI 密码

自 v1.2.8 起可直接用命令重置，**不需要操作数据库**：

```bash
cd /opt/data          # 切到 biliup 服务的工作目录
biliup user list      # 先看有哪些账号
biliup user reset-password <用户名>
```

新密码会从终端提示输入（或从标准输入读一行），重置后该用户的所有会话会失效，需重新登录。

::: warning
如果服务版本较旧、没有 `biliup user` 命令，才需要退回操作数据库的方式。直接删除 `data/data.sqlite3` 会**丢失全部配置、账号、主播与历史记录**，操作前务必先备份。
:::

### WebUI 响应缓慢

- 检查服务器资源（CPU / 内存 / 磁盘）是否充足，可在控制台查看
- 降低日志级别（DEBUG 级别会产生大量日志影响性能）
- 减少同时录制的直播间数量
